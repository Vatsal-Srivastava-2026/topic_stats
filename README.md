# topic_stats

A standalone ROS 2 Python package for measuring a topic's received frequency,
inter-arrival gaps, and burstiness. It discovers the message type at runtime, so
it works with arbitrary ROS 2 message types available in the sourced environment.

## Build

From the `~/ca1n` workspace:

```bash
source /opt/ros/humble/setup.bash
PYTHONNOUSERSITE=1 colcon build --symlink-install --packages-select topic_stats
source install/setup.bash
```

## Run

```bash
ros2 run topic_stats topic_stats /radar/points
```

Omit the topic name to discover topics with active publishers and select one by
index:

```bash
ros2 run topic_stats topic_stats
```

Useful options:

```bash
# Capture for 60 seconds with custom analysis windows
ros2 run topic_stats topic_stats /radar/points \
  --duration 60 --windows 10 5 1 0.5 0.1 0.05

# Repeated captures, stopping after one completely silent capture
ros2 run topic_stats topic_stats /radar/points --loop

# Force subscriber reliability and choose an output base directory
ros2 run topic_stats topic_stats /radar/points \
  --qos-reliability best_effort --output-dir /tmp/topic_stats
```

Run `ros2 run topic_stats topic_stats --help` for all options.

Unless `--output-dir` is supplied, reports are written under the package's
`out/` directory. A single non-looping run creates
`stats_<topic>_YYMMDD_HHMMSS/` and writes its results directly into that
directory. Results use the same analysis-oriented folders as `rosbag_stats`:

```text
stats_<topic>_YYMMDD_HHMMSS/
├── arrival_gaps/
├── header_gaps/
├── throughput_arrival/
├── throughput_header/
├── source_latency/
├── data/
├── publisher_info/
└── summary.txt
```

With `--loop`, timestamped capture directories are created inside the session
directory, and cross-capture statistics are written under `consolidated/`.
Neither layer is created for a normal non-looping run.

The live-topic executable measures arrivals with `time.monotonic_ns()` in its
subscription callback and also extracts `msg.header.stamp` when available. It
now produces burstiness/window plots and gap statistics for both timestamp
sources. The normalized drift plot is:

```text
(arrival - first arrival) - (header - first header)
```

This removes the constant offset between the monotonic arrival clock and the
header's ROS/system clock, exposing accumulating timing or latency drift. Topics
without `msg.header.stamp` still receive complete subscriber-arrival analysis.

## Analyze multiple live topics

`multi_topic_stats` loads its candidates and settings from the source package's
`config/live_topic_stats.yaml` by default. If that config has no topics, it
discovers active topics and accepts multiple indices, ranges, names, or `all`.
It launches one independent `topic_stats` process per selected topic:

```bash
ros2 run topic_stats multi_topic_stats
```

You can also provide candidate topics directly:

```bash
ros2 run topic_stats multi_topic_stats \
  --topics /camera/image_raw /imu/data \
  --duration 60 --windows 5 1 0.5 0.1 \
  --output-dir /tmp/live_topic_stats
```

Child output is prefixed with its topic name. Ctrl-C is forwarded to every child
so each analyzer can save its partial capture before exiting.

Each invocation creates one shared output directory. Like `rosbag_stats`, all
topics share analysis-specific directories and topic names are encoded in the
filenames (for example, `/camera/image_raw` becomes `camera_image_raw`):

```text
multitopic_stats_YYMMDD_HHMMSS/
├── arrival_gaps/
│   ├── camera_image_raw_arrival_gaps.png
│   └── imu_data_arrival_gaps.png
├── header_gaps/
├── throughput_arrival/
├── throughput_header/
├── source_latency/
├── data/
├── publisher_info/
├── summary.txt
├── all_topics_arrival_timestamp_gaps.png
├── all_topics_header_timestamp_gaps.png
├── all_topics_arrival_throughput.png
├── all_topics_header_throughput.png
└── all_topics_source_latency.png
```

There are no topic-specific directories. The five root-level plots condense all
successfully analyzed topics; their legends report only mean ± standard
deviation. Each topic's arrival and header throughput folder contains only its
combined plot with all configured window sizes; redundant per-window PNGs are
not generated by `multi_topic_stats`. In loop mode, shared timestamped capture
directories are created, each using this same flat rosbag-style layout, and
topic-prefixed cross-capture files are written in `consolidated/`.

Before launching configured or command-line topics, the wrapper observes the ROS
graph for `discovery_timeout` seconds. Only candidate topics seen with at least
one active publisher during that window are launched. Missing topics are listed
as skipped instead of leaving analyzer processes waiting forever. If none of the
candidates appear, the wrapper exits with an error and launches no analyzers.

### YAML configuration

The default config is loaded directly from the source package—not from
`install/share`—at:

```text
~/ca1n/src/topic_stats/config/live_topic_stats.yaml
```

Example:

```yaml
topics:
  - /camera/image_raw
  - /imu/data
duration: 30.0
windows: [2.0, 1.0, 0.5, 0.25, 0.1]
output_dir: /tmp/live_topic_stats
qos_depth: 1000
qos_reliability: auto
loop: false
measure_bytes: false
discovery_timeout: 2.0
include_system_topics: false
```

Running without `--config` uses that file automatically. To use a different
file, override it explicitly:

```bash
ros2 run topic_stats multi_topic_stats \
  --config /path/to/another_live_topic_stats.yaml
```

Command-line values override their corresponding config values. Set `topics: []`
or omit `topics` to retain interactive multi-topic selection while loading the
remaining settings from YAML. `discovery_timeout` controls both this interactive
scan and the validation window applied to configured topics.

## Analyze a rosbag

`rosbag_stats` performs full-duration analysis of a ROS 2 bag using both:

- the timestamp stored by rosbag2 when the recorder received/recorded a message;
- `msg.header.stamp`, when that message type contains a usable header.

Run it with the directory that contains `metadata.yaml` and the MCAP/DB3 file:

```bash
source /opt/ros/humble/setup.bash
source ~/ca1n/install/setup.bash
ros2 run topic_stats rosbag_stats /path/to/rosbag_directory
```

The command prints every topic whose metadata reports at least one message and
prompts for 1-based topic indices. Selections accept spaces, commas, ranges, or
`all`, for example:

```text
Select topic indices (for example: 1 3-5), topic names, or 'all': 1,3-5
```

While processing, stdout shows the current phase and progress. Bag reading
reports messages processed, percentage, rate, estimated time remaining, and the
current topic. Result generation uses a second progress bar that identifies the
CSV, individual plot, aggregate plot, or report currently being produced. In an
interactive terminal the bars update in place; redirected output uses periodic
plain-text progress lines.

For scripts and unattended runs, provide the selection on the command line:

```bash
ros2 run topic_stats rosbag_stats /path/to/bag --select all
ros2 run topic_stats rosbag_stats /path/to/bag --select 1 3-5
ros2 run topic_stats rosbag_stats /path/to/bag \
  --select /camera/image_raw /imu/data
```

Use `--list-only` to print the nonempty topic inventory without analyzing it.
Use `--windows` to choose throughput bin widths:

```bash
ros2 run topic_stats rosbag_stats /path/to/bag \
  --select all --windows 10 5 1 0.5 0.1
```

Results are written directly to `<bag_directory>/stats/`. The root contains:

- `summary.txt` with count, mean, minimum, maximum, standard deviation, and
  percentile statistics;
- `topic_inventory.txt`, including the original message counts and selection;
- all-topic header-gap and recorder-arrival-gap plots;
- all-topic header-based and recorder-arrival-based throughput plots;
- an all-topic normalized source-to-recorder latency plot.

Individual topic plots are grouped by plot type rather than by topic:

```text
stats/
├── arrival_gaps/
├── header_gaps/
├── throughput_arrival/
├── throughput_header/
├── source_latency/
└── data/
```

The `data/` CSV files preserve each message's recorder timestamp, usable header
timestamp, elapsed times, raw recorder-minus-header latency, and normalized
latency. Normalized latency subtracts the first valid latency for that topic,
which removes a constant clock offset and makes growing or shrinking latency
visible. Topics without `msg.header.stamp` still receive recorder-arrival and
throughput analysis; header and source-latency outputs explicitly show that the
data is unavailable.

## Troubleshooting Python package conflicts

If `colcon build` fails inside `setuptools` or `distutils` while loading packages
from `~/.local/lib/python3.10/site-packages`, build with user-site Python
packages disabled:

```bash
source /opt/ros/humble/setup.bash
PYTHONNOUSERSITE=1 colcon build --symlink-install --packages-select topic_stats
```

This setting applies only to the build command and does not uninstall or modify
anything in `~/.local`. Python instead uses the mutually compatible Ubuntu and
ROS Python packages.

If the same user/system Matplotlib conflict produces warnings when running an
analysis, apply the setting to the executable as well:

```bash
PYTHONNOUSERSITE=1 ros2 run topic_stats rosbag_stats /path/to/bag
```

Matplotlib must therefore be available as a system package. Install it with:

```bash
sudo apt update
sudo apt install python3-matplotlib
```

You can verify the system installation while ignoring user-site packages with:

```bash
PYTHONNOUSERSITE=1 python3 -c \
  'import matplotlib; print(matplotlib.__version__); print(matplotlib.__file__)'
```

Alternatively, when preparing a ROS workspace, `rosdep` can install declared
dependencies such as `python3-matplotlib`:

```bash
rosdep install --from-paths src --ignore-src -r -y
```
